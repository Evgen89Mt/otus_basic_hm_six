Пара замечаний для роста:

1. Использование std::move вместо static_cast
В коде вы везде пишите static_cast(v). Это технически абсолютно верно (именно это и делает std::move), но в современном C++ принято подключать #include  и использовать std::move(v). Это делает код гораздо читаемее и является стандартом индустрии.
- [реализованно];

2. Копирование вместо перемещения при реаллокации вектора
В методе NewVector::reallocate вы выделяете новую память и переносишь элементы из старой:

for(size_t i = 0; i < m_size; ++i){
    new(&newData[i]) T(m_data[i]); // ЗДЕСЬ ПРОИСХОДИТ КОПИРОВАНИЕ
    m_data[i].~T();                 
}

Если вектор хранит "тяжелые" объекты (например, строки или другие векторы), реаллокация будет медленной. Лучше объекты перемещать:

new(&newData[i]) T(std::move(m_data[i])); // Теперь работает конструктор перемещения

for(size_t i = 0; i < m_size; ++i){
    new(&newData[i]) T(std::move(m_data[i]));
    m_data[i].~T();                 
}
- [реализованно];

3. Метод swap в списках (DoubleList и SingleList)
Ваша реализация:

T tmp = static_cast(a->value);
a->value = static_cast(b->value);
b->value = static_cast(tmp);

Вы меняете местами значения внутри узлов (Node). Это работает и для учебной задачи вполне допустимо. Однако в стандартной библиотеке (например, std::list) при swap перевязываются указатели узлов (prev и next), а сами объекты не трогаются. Это делается для того, чтобы итераторы и ссылки на элементы оставались валидными после обмена.
- [не реализованно];

4. Итераторы и const
У вас хорошо написан класс итератора с двумя шаблонными параметрами VecIterator, где U может быть const T.
Небольшой недочет заключается в том, что обычно методы константного итератора возвращают константные ссылки. В вашем коде константный итератор позволяет читать данные, но структура не предусматривает неявного приведения обычного итератора к константному (что бывает полезно). Но для текущего уровня это реализовано очень достойно.
